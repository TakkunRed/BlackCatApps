# MEGA MERGE

オリジナルのパズルゲームです。ブロック崩しのように並んだ「2の累乗」の数字ブロックを列ごとにタップし、
2048を目指して合体させていきます。特定の既存ゲームの移植・模倣ではなく、独自に考案したルールです。

## 遊び方

0. 画面上部の **4×4 / 5×5 / 6×6** から盤面サイズを選ぶ(各サイズのクリア最小ショット数の自己ベストが
   ボタン下に表示される)。選ぶと即座にそのサイズで新しいゲームが始まる
1. 画面をタップしてスタート
2. **盤面上のどのブロックでも直接タップ/クリック**(またはキーボードの数字キー `1`〜列数でその列の一番手前を撃つ)。
   狙ったブロックが**即座に2倍**になる
3. そのとき、上下左右の隣接ブロックに**「直撃前の元の値」または「2倍になった後の値」のどちらかと一致する**ものが
   あれば**合体してさらに2倍**。前後左右で同時に複数一致した場合は、1個だけ選ぶのではなく**一致したもの全部を
   その場で一気に合体**する(優先順位で1個だけ、という制限は無い)。合体後の数字がまた隣と一致すれば連鎖し、
   連鎖が長いほど得点ボーナスが大きくなる
   - 例: 横一列に同じ数字が3つ並んでいて真ん中を撃つと、両隣が同時に一致するので3つとも一気に合体する
   - 例: 十字型に同じ数字が4つ並んでいる中心を撃つと、4方向すべてが一気に合体する
   - 同時に吸収したブロックが多いほど、画面の演出(中心ブロックが大きく弾む)も得点の連鎖ボーナスも大きくなる
   - 2回目以降の連鎖(同じ一撃の中でさらに合体が続くとき)は一拍おいて再生され、「CHAIN 2」「CHAIN 3」の
     ようなラベルが浮かぶので、何連鎖したかが一目で分かる
4. **2048に到達したブロックはポップして消滅**する
5. 合体やポップで空いたマスには、同じ列の上にあるブロックが**重力で落ちてくる**。
   どの列を撃つかで盤面の並びが実際に作り変わっていく
6. **列が完全に空になると、左右の列が詰まって隙間が無くなる**。盤面が進むほど残ったブロック同士が
   自然に近づくので、終盤でも「打つしかない」状態になりにくい
7. **ショットには上限がある**(盤面サイズに比例、6×6なら130発・5×5なら90発・4×4なら58発)。
   使い切る前に撃ち尽くすと **OUT OF AMMO** でゲームオーバー
8. 盤面のブロックを全て消すと **ALL CLEAR**。その盤面サイズでの自己ベスト(最小ショット数)を更新すると
   **NEW BEST!!** と表示される
9. HUDの **TARGET** は、その盤面を「だいたいこのくらいの手数で消せるはず」という目安のショット数
   (ビームサーチによる見積もり。厳密な最短手数の証明ではない)。**USED** は現在までに使ったショット数で、
   TARGETを超えるとオレンジ色に変わり、一目で「もう目標オーバーした」と分かるようにしてある
10. ⏸ PAUSEボタン(またはキーボードの `P`)でいつでも一時停止/再開
11. 最高得点は端末に保存され、次回スタート時に表示される(クリアできなくても、その回のスコアが新記録なら更新される)

## 設計の変遷

v1は「同じマスを撃ち続ければ必ず勝ててしまう」設計だったため(プレイヤーの選択がほぼ結果に影響しないことをシミュレーションで確認)、
v2で**重力落下**と**弾数制限(130発)**を追加しました。重力により「どの列を撃つか」が盤面を実際に作り変えるようになり、
シミュレーションでは1手先読み戦略で平均105発・ランダム戦略で平均161発という有意な差が出ています。
弾数上限130発は、先読み戦略の成功率95%・ランダム戦略の成功率6%になるよう調整した値です。

v2.1では、実際に遊んだフィードバックを受けてさらに2点改善しました。

- **合体の過程が見えなかった問題**: それまでは連鎖・重力・列詰めが一瞬で結果だけ反映されていたため、
  「何が起きたか分からない」「連鎖しているかも分からない」状態でした。ロジック自体は即時確定のまま、
  起きたことの詳細(どの位置が合体したか・何が何マス落ちたか・どの列がどこへ詰まったか)を記録し、
  画面側でその記録を順番に再生する形でアニメーション化しています。
- **終盤・列が孤立すると「打つだけ」になる問題**: 重力が列の中だけで完結していたため、隣の列が
  無くなるとそれ以上合体のしようがありませんでした。列が完全に空になったときに左右の列を詰める
  処理を追加し、残りが少なくなるほど自然に隣接のチャンスが生まれるようにしています。

v3では、さらに遊んだフィードバックを受けて3点見直しました。

- **シューティングが形だけだった問題**: 弾は常に列の一番手前(下)のブロックにしか当たらず、自機を動かして
  「狙う」こと自体に実質的な意味がありませんでした。自機・弾の移動を廃止し、列をタップ/クリックした瞬間に
  即座に解決するシンプルな操作に変更しました。
- **合体できる組み合わせが狭すぎた問題**: 以前は「直撃後に2倍になった値」としか合体判定していなかったため、
  隣り合う2つの同じ数字(直撃前の値同士)が合体できませんでした。直撃前の元の値でも隣接マッチできるように
  ロジックを拡張し、今までアクションの起こしようがなかった組み合わせでも合体できるようにしました。
- **クリアの目標が無かった問題**: 盤面の配置から「クリアに必要そうな手数」をビームサーチで見積もり、
  TARGETとして表示するようにしました。厳密な最短手数の算出は組み合わせ爆発のため非現実的ですが、
  実用上十分な強い目安になっています。

v4では、さらに2点見直しました。

- **列の最前面しか対象にならず、タップの手間の割に動きが少ない問題**: 「下の1マスしか対象にならないなら
  シューティングでなくタップでいい」という指摘はv3で既に取り入れていましたが、さらに「盤面上のどのブロック
  でもタップできるように」という要望を受け、列単位ではなくマス単位でタップできるようにしました。奥にある
  ブロックを直接狙うこともでき、重力で落ちてきた後の並びも自分で作り変えやすくなりました。
- **横に同じ数字が並んでも、合体するのは2つまでだった問題**: 従来は上下左右の優先順位に沿って1個だけを
  選んで合体させていたため、「前後左右で同じ数字が揃っても一気に合体はしない」状態でした。前後左右の同時
  一致を全部まとめて吸収する方式に変更し、3つ並びの真ん中を撃てば3つとも、十字型に4つ揃えば4つとも一気に
  合体するようにしました。スコアも吸収した数ぶん個別に連鎖ボーナスが積み上がるので、損をした感じにはなりません。
  あわせて、同時に多く吸収するほど合体演出(中心ブロックの弾み・発光)が大きくなるようにして、ダイナミックさを
  見た目でも感じられるようにしています。

v5では、さらに遊んだフィードバックを受けて4点見直しました。

- **連続合体(連鎖)が起きたのか分からない問題**: 連鎖の2段階目以降が前の合体とほぼ同じ見た目・速さで
  続けて再生されるため、「何連鎖したのか」が伝わりにくい状態でした。各段階の表示時間を全体的に延ばし、
  2回目以降の合体の直前に一拍の間(ポーズ)を挟んで前の合体と視覚的に分離し、「CHAIN 2」「×3」のような
  ラベルをその場に浮かせて明示するようにしました。合体を待つ動きそのものも「ほぼ原寸のまま飛び込んで
  直前でスッと消える」よう調整し、中心ブロックが先に大きく弾んでから周りのブロックが上に重なって
  見えるよう描画順序も直しました(インパクトを強め、何が起きたか視認しやすくするため)。
- **盤面サイズが6×6固定で、サイズ別の記録がなかった問題**: 4×4・5×5・6×6から盤面サイズを選べるようにし、
  サイズごとに「クリアに使った最小ショット数」を自己ベストとして個別に記録・表示するようにしました。
  ショット上限もサイズに比例して自動調整されます(6×6=130発を基準比率に換算)。盤面が小さいほどセルが
  大きく表示されるので、短時間で遊べる手軽な難易度としても機能します。
- **ブロックの見た目が地味な問題**: 単色べた塗りだった見た目を、縦グラデーション・縁取り・角丸のある
  立体的な見た目に変更しました。文字サイズもセルの大きさに応じて自動調整するようにし(特に4×4では
  セル自体が大きくなるぶん文字も大きく表示される)、全体的に視認性を上げています。
- **ショット数の進捗が分かりにくい問題**: HUDの表示を「SHOTS LEFT(残り)」から「USED(使用数)」に変更し、
  現在までに使ったショット数をそのまま表示するようにしました。TARGETを超えた時点でUSEDの表示色が
  オレンジに変わるので、暗算しなくても一目で「目標を超えたかどうか」が分かります。

## 得点ルール

各合体ステップの得点 = そのステップで到達した数字 × (1 + 連鎖回数 × 0.5)。
たとえば合体なしの直撃は等倍、1連鎖なら1.5倍、2連鎖なら2倍…と、連鎖が伸びるほど
「数字の指数的な伸び」と「連鎖ボーナスの線形な伸び」が掛け合わさって得点が跳ね上がる設計です。
2048へのポップ時はさらに固定ボーナスが加算されます。

## 技術構成

- 素のHTML / CSS / JavaScript(ビルド不要、フレームワーク依存なし)、描画は Canvas 2D
- ゲームロジック(`js/game.js`)は描画・DOMに依存しない純粋な状態machineとして実装し、Node上で直接ユニットテスト可能
- PWA対応(`manifest.json` + `sw.js` でオフライン動作・ホーム画面追加に対応、ネットワーク優先キャッシュ戦略)
- 外部ライブラリ・フォント・画像アセットのネットワーク依存なし

```
mega-merge/
  index.html
  css/style.css        筐体・HUD・サイズ選択ボタン・ヒントテキストのスタイル
  js/
    game.js             ゲームロジック(描画非依存、テスト対象)。合体解決・重力・列詰め・
                         TARGET見積もり(ビームサーチ)の純粋関数、盤面サイズ切り替え
                         (setGridSize)・サイズ別自己ベスト記録(getBestShots)を含む
    render.js             Canvas描画(数字・色分け・ホバーセルハイライト・CHAINラベル)
    app.js                 ゲームループ・入力(タップ/クリック/数字キー/サイズ選択ボタン)・
                            合体のアニメーション再生・サウンド・PWA登録
  manifest.json / sw.js  PWA設定
  test/                  ロジックの回帰テスト(フレームワーク無し)
```

### 盤面サイズの切り替えについて(実装メモ)

`GRID_ROWS`/`GRID_COLS`/`CELL_W`/`CELL_H`/`SHOT_LIMIT` はESモジュールの**ライブバインディング**
(`export let` + 再代入)として実装しています。`setGridSize(rows, cols)` を呼ぶとこれらの値が
更新され、他ファイルが `import { GRID_ROWS } from './game.js'` のように読み込んでいる場合でも
再importなしに最新値が見えます。盤面の実ピクセルサイズ(`FIELD_W`/`FIELD_H`、Canvasの解像度)は
サイズによらず固定で、代わりにセル1個分のサイズ(`CELL_W`/`CELL_H`)が盤面サイズに応じて伸縮します
(4×4ほどセルが大きく、6×6で現行のサイズに戻ります)。

## 既知の簡略化・今後の案

- 今後の拡張案として、ブロック全体が徐々に降りてくる「降下モード」も検討可能(現状、重力は列の中だけ・列の詰めは水平方向のみ)
- 初期盤面はランダム生成(2,2,2,4,4,8の重み付き抽選)。特定のパズルが必ず解けることは保証していない
- 弾数上限(6×6=130発を基準にサイズ比例)・連鎖ボーナス倍率・ポップ閾値(2048)は、いずれもシミュレーションを
  根拠にした調整値で、今後のバランス変更の余地がある
- TARGETはビームサーチによる見積もりであり、理論上の最短手数を証明したものではない
- アニメーション再生中はタップ/キー入力を一時的に無視する(連打してもショットは消費されない)
- 盤面サイズを切り替えると(アニメーション再生中を除き)即座に新しいゲームが始まる。プレイ中のサイズ変更に
  「本当に切り替えますか」のような確認は挟んでいない(カジュアルなパズルという位置づけのため)
- サイズ別の自己ベストはブラウザのlocalStorageに保存される端末ローカルの記録で、複数端末間の同期はしていない
