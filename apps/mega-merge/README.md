# MEGA MERGE

オリジナルのパズルゲームです。ブロック崩しのように並んだ「2の累乗」の数字ブロックをタップして合体させ、
盤面を最後の1個になるまで集約していきます。特定の既存ゲームの移植・模倣ではなく、独自に考案したルールです。

## 遊び方

0. 画面上部の **4×4 / 5×5 / 6×6** から盤面サイズを選ぶ(各サイズのクリア最小ショット数の自己ベストが
   ボタン下に表示される)。選ぶと即座にそのサイズで新しいゲームが始まる
1. 画面をタップしてスタート
2. **盤面上のどのブロックでも直接タップ/クリック**(またはキーボードの数字キー `1`〜列数でその列の一番手前を撃つ)。
   狙ったブロックが**即座に2倍**になる
3. そのとき、上下左右の隣接ブロックに**「直撃前の元の値」または「2倍になった後の値」のどちらかと一致する**ものが
   あれば**合体してさらに2倍**。前後左右で同時に複数一致した場合は、1個だけ選ぶのではなく**一致したもの全部を
   その場で一気に合体**する(優先順位で1個だけ、という制限は無い)。合体後の数字がまた隣と一致すれば連鎖し、
   連鎖が長いほど得点ボーナスが大きくなる
   - 例: 横一列に同じ数字が3つ並んでいて真ん中を撃つと、両隣が同時に一致するので3つとも一気に合体する
   - 例: 十字型に同じ数字が4つ並んでいる中心を撃つと、4方向すべてが一気に合体する
   - 同時に吸収したブロックが多いほど、画面の演出(中心ブロックが大きく弾む)も得点の連鎖ボーナスも大きくなる
   - 2回目以降の連鎖(同じ一撃の中でさらに合体が続くとき)は一拍おいて再生され、「CHAIN 2」「CHAIN 3」の
     ようなラベルが浮かぶので、何連鎖したかが一目で分かる
4. **2048を超えても合体したブロックは消えない**。値がどれだけ大きくなっても盤面に残り続け、
   さらに大きな数字へと合体を続けられる(ポップのような消滅演出は無い)
5. 合体で空いたマスには、同じ列の上にあるブロックが**重力で落ちてくる**。
   どの列を撃つかで盤面の並びが実際に作り変わっていく
6. **列が完全に空になると、左右の列が詰まって隙間が無くなる**。盤面が進むほど残ったブロック同士が
   自然に近づくので、終盤でも「打つしかない」状態になりにくい
7. **ショット数に上限はない**。何発使っても必ずクリアできる(弾切れによるゲームオーバーは無い)。
   その代わり、ゲームの目的は**できるだけ少ないショット数でクリアすること**そのものになる
8. **盤面のブロックが最後の1個になると COMPLETE!**。その盤面サイズでの自己ベスト(最小ショット数)を
   更新すると、紙吹雪と共に金色の **NEW BEST!!** が弾けるように表示される
9. クリア画面では、今回使った **SHOTS(ショット数)を大きく**、その下に「4×4 BEST 7」のような
   縦長のバッジでそのサイズの自己ベストを表示する。SCOREや最後の1個の値などは出さず、
   「何発でクリアできたか」が一目で分かることだけに絞ってある
10. HUDの **BEST** はその盤面サイズの自己ベスト(最小ショット数)、**SHOTS** は今回使ったショット数。
    「SHOTSがBESTを下回れば新記録」という、シンプルな最小手数競争になっている
11. ⏸ PAUSEボタン(またはキーボードの `P`)でいつでも一時停止/再開
12. 最高得点は端末に保存され、次回スタート時に表示される(クリアできなくても、その回のスコアが新記録なら更新される)
13. **？ 遊び方** ボタンで、このルール説明をダイアログとして開ける(常時は表示しない)

## 設計の変遷

v1は「同じマスを撃ち続ければ必ず勝ててしまう」設計だったため(プレイヤーの選択がほぼ結果に影響しないことをシミュレーションで確認)、
v2で**重力落下**と**弾数制限(130発)**を追加しました。重力により「どの列を撃つか」が盤面を実際に作り変えるようになり、
シミュレーションでは1手先読み戦略で平均105発・ランダム戦略で平均161発という有意な差が出ています。
弾数上限130発は、先読み戦略の成功率95%・ランダム戦略の成功率6%になるよう調整した値です。

v2.1では、実際に遊んだフィードバックを受けてさらに2点改善しました。

- **合体の過程が見えなかった問題**: それまでは連鎖・重力・列詰めが一瞬で結果だけ反映されていたため、
  「何が起きたか分からない」「連鎖しているかも分からない」状態でした。ロジック自体は即時確定のまま、
  起きたことの詳細(どの位置が合体したか・何が何マス落ちたか・どの列がどこへ詰まったか)を記録し、
  画面側でその記録を順番に再生する形でアニメーション化しています。
- **終盤・列が孤立すると「打つだけ」になる問題**: 重力が列の中だけで完結していたため、隣の列が
  無くなるとそれ以上合体のしようがありませんでした。列が完全に空になったときに左右の列を詰める
  処理を追加し、残りが少なくなるほど自然に隣接のチャンスが生まれるようにしています。

v3では、さらに遊んだフィードバックを受けて3点見直しました。

- **シューティングが形だけだった問題**: 弾は常に列の一番手前(下)のブロックにしか当たらず、自機を動かして
  「狙う」こと自体に実質的な意味がありませんでした。自機・弾の移動を廃止し、列をタップ/クリックした瞬間に
  即座に解決するシンプルな操作に変更しました。
- **合体できる組み合わせが狭すぎた問題**: 以前は「直撃後に2倍になった値」としか合体判定していなかったため、
  隣り合う2つの同じ数字(直撃前の値同士)が合体できませんでした。直撃前の元の値でも隣接マッチできるように
  ロジックを拡張し、今までアクションの起こしようがなかった組み合わせでも合体できるようにしました。
- **クリアの目標が無かった問題**: 盤面の配置から「クリアに必要そうな手数」をビームサーチで見積もり、
  TARGETとして表示するようにしました。厳密な最短手数の算出は組み合わせ爆発のため非現実的ですが、
  実用上十分な強い目安になっています。

v4では、さらに2点見直しました。

- **列の最前面しか対象にならず、タップの手間の割に動きが少ない問題**: 「下の1マスしか対象にならないなら
  シューティングでなくタップでいい」という指摘はv3で既に取り入れていましたが、さらに「盤面上のどのブロック
  でもタップできるように」という要望を受け、列単位ではなくマス単位でタップできるようにしました。奥にある
  ブロックを直接狙うこともでき、重力で落ちてきた後の並びも自分で作り変えやすくなりました。
- **横に同じ数字が並んでも、合体するのは2つまでだった問題**: 従来は上下左右の優先順位に沿って1個だけを
  選んで合体させていたため、「前後左右で同じ数字が揃っても一気に合体はしない」状態でした。前後左右の同時
  一致を全部まとめて吸収する方式に変更し、3つ並びの真ん中を撃てば3つとも、十字型に4つ揃えば4つとも一気に
  合体するようにしました。スコアも吸収した数ぶん個別に連鎖ボーナスが積み上がるので、損をした感じにはなりません。
  あわせて、同時に多く吸収するほど合体演出(中心ブロックの弾み・発光)が大きくなるようにして、ダイナミックさを
  見た目でも感じられるようにしています。

v5では、さらに遊んだフィードバックを受けて4点見直しました。

- **連続合体(連鎖)が起きたのか分からない問題**: 連鎖の2段階目以降が前の合体とほぼ同じ見た目・速さで
  続けて再生されるため、「何連鎖したのか」が伝わりにくい状態でした。各段階の表示時間を全体的に延ばし、
  2回目以降の合体の直前に一拍の間(ポーズ)を挟んで前の合体と視覚的に分離し、「CHAIN 2」「×3」のような
  ラベルをその場に浮かせて明示するようにしました。合体を待つ動きそのものも「ほぼ原寸のまま飛び込んで
  直前でスッと消える」よう調整し、中心ブロックが先に大きく弾んでから周りのブロックが上に重なって
  見えるよう描画順序も直しました(インパクトを強め、何が起きたか視認しやすくするため)。
- **盤面サイズが6×6固定で、サイズ別の記録がなかった問題**: 4×4・5×5・6×6から盤面サイズを選べるようにし、
  サイズごとに「クリアに使った最小ショット数」を自己ベストとして個別に記録・表示するようにしました。
  ショット上限もサイズに比例して自動調整されます(6×6=130発を基準比率に換算)。盤面が小さいほどセルが
  大きく表示されるので、短時間で遊べる手軽な難易度としても機能します。
- **ブロックの見た目が地味な問題**: 単色べた塗りだった見た目を、縦グラデーション・縁取り・角丸のある
  立体的な見た目に変更しました。文字サイズもセルの大きさに応じて自動調整するようにし(特に4×4では
  セル自体が大きくなるぶん文字も大きく表示される)、全体的に視認性を上げています。
- **ショット数の進捗が分かりにくい問題**: HUDの表示を「SHOTS LEFT(残り)」から「USED(使用数)」に変更し、
  現在までに使ったショット数をそのまま表示するようにしました。TARGETを超えた時点でUSEDの表示色が
  オレンジに変わるので、暗算しなくても一目で「目標を超えたかどうか」が分かります。

v6では、さらに遊んだフィードバックを受けて3点見直しました。

- **TARGET(目安のショット数)と残りショット数の表示が不要になった**: 「ターゲットは不要、残り回数もやめて、
  最小回数を競うようにしたい」という要望を受け、ビームサーチによるTARGET見積もりと、弾数上限(撃ち尽くすと
  ゲームオーバーになる仕組み)を完全に廃止しました。ショット数に上限は無くなり、HUDは「SCORE / BEST / SHOTS」
  とシンプルになりました。目指すのは理論上の目安ではなく、自分が実際に出した自己ベストの更新そのものです。
- **自己ベスト更新時の演出が地味だった**: 「もっと派手にして」という要望を受け、新記録クリア時は紙吹雪が
  画面に舞い、「NEW BEST!!」のタイトルが弾むように拡大しながら金色に光り続けるアニメーションを追加しました。
  効果音も上昇する3音のファンファーレに変更しています。通常のクリア(自己ベストを更新しない場合)は
  従来どおり控えめな演出のままにして、メリハリを付けています。また、この演出がしっかり見えるよう、
  クリア直後の合体アニメーションが終わるまでオーバーレイの表示自体を遅らせるようにしました
  (以前は合体の様子が隠れてしまっていました)。
- **連続合体したことが音で分からなかった**: それまで効果音はショットを撃った瞬間にまとめて1回鳴るだけ
  だったため、何段階連鎖したかが耳では分かりませんでした。効果音をアニメーションの各段階が実際に
  画面に現れたタイミングに同期させ、連鎖が深いほど・同時吸収が多いほど音程と音量が上がるようにしました。

v7では、さらに2点見直しました。

- **文字が全体的に小さい**: HUD・オーバーレイ・ヒント・クレジット・サイズ選択ボタンなど、DOM側のテキストを
  軒並り大きくしました(例: HUDの数字は16px→21px、オーバーレイタイトルは15px→21px)。Canvas側のブロック内
  数字・CHAINラベルの基準サイズも底上げしています。
- **「2048にならないと消えない」をやめ、最後の1個になるまでの最小回数を競うゲームにしたい**: 2048到達で
  ポップして消滅する仕組みを完全に廃止しました。合体した側のブロックは値がいくつになっても消えずに盤面に
  残り続け、クリア条件は「盤面のブロックが最後の1個になること」に変わりました(2048という特定の数字は
  もう関係ありません)。値に上限が無くなったぶん、ブロック内の数字は桁数から逆算して自動的に縮小し、
  何桁になっても枠からはみ出さないようにしています。ポップボーナス(+500点)も、ポップ自体が無くなった
  ため廃止しました。

v8では、「説明の字が多すぎて上部が画面からはみ出す」という指摘を受け、常時表示していたヒント文・
クレジット文を廃止し、**？ 遊び方** ボタンをタップしたときだけ開くダイアログに統合しました。普段の画面は
盤面サイズ選択・HUD・盤面・PAUSE/SOUND/？遊び方の3ボタンだけになり、縦に小さいモバイル画面(高さ640px
程度)でもスクロール無しで全体が収まることを確認しています。

v9では、「クリア画面のショット数をもっと大きく、最後の1個や自己ベストの文章は不要」という要望を受け、
クリア時のオーバーレイを再設計しました。「最後の1個: X」「SCORE」「自己ベスト: X発」という3行の文章を
やめ、代わりに**SHOTS(今回のショット数)を58pxの大きな数字で主役として表示**し、その下に
「4×4 / BEST / 7」のように盤面サイズ・ラベル・自己ベストの数字を縦に積んだバッジを添えるだけに
絞りました。これにより「何発でクリアできたか」が一目で分かるようになっています。

v10では、「だいぶ面白くなってきた」というフィードバックとともに3点の改善要望を受けました。

- **ブロックの色をもっとカラフルに**: 色相の割り当てを単純な等間隔刻み(18°→47°)から**黄金角
  (約137.5°)刻み**に変更しました。等間隔刻みだと、序盤によく出る小さい指数(2,4,8…)の色相が
  近い位置に固まって地味に見えてしまいますが、黄金角を使うと隣り合う値同士の色相が常に大きく離れ、
  序盤から緑・紫・金色のようにはっきり異なる色が出るようになります。彩度も70%→78%に上げました。
  あわせて、色相の幅が広がったことで「値が大きいほど明るい文字色」という従来の判定が合わなくなったため、
  文字は常に明るい色+暗い縁取りで描くようにし、どの背景色でも読めるようにしています。
- **連続合体の音を音階にする**: 「1つはド、2つはレ、3つはミ」という提案を受け、連鎖の深さに応じた
  周波数計算式をやめ、**ハ長調の音階(ド・レ・ミ・ファ・ソ・ラ・シ、2オクターブ分)**を順に鳴らすように
  変更しました。波形もsawtoothからtriangleに変え、短いブザー音ではなく聞き取りやすい「音」として
  連鎖の深さが分かるようにしています。
- **最後の1個になったら黒猫ロゴを表示**: 盤面がちょうど1個になったとき、そのブロックの中にBlackCatApps
  のマスコットである黒猫ロゴ(`icons/cat-logo.png`、サイトルートの`assets/logo.png`と同じ画像)を
  数字の代わりに表示するようにしました。アニメーション中は非同期に判定しているため、合体の演出が
  終わって本当に1個だけになった瞬間に自然と現れます。

v11では、「色をもう少しかっこいい配色にして」という要望を受け、v10で導入した黄金角による機械的な
虹色の割り当てをやめ、**手作業で選んだネオン系のパレット**(シアン・バイオレット・ホットピンク・
ティール・エレクトリックブルー・アンバーなど12色)に差し替えました。UIのアクセントカラー
(`--violet: #a78bfa`)と同系統の色も含め、暗い背景に映える方向性で統一し、隣り合う値同士で似た色相が
連続しないように並べています。

## 得点ルール

各合体ステップの得点 = そのステップで到達した数字 × (1 + 連鎖回数 × 0.5)。
たとえば合体なしの直撃は等倍、1連鎖なら1.5倍、2連鎖なら2倍…と、連鎖が伸びるほど
「数字の指数的な伸び」と「連鎖ボーナスの線形な伸び」が掛け合わさって得点が跳ね上がる設計です。

## 技術構成

- 素のHTML / CSS / JavaScript(ビルド不要、フレームワーク依存なし)、描画は Canvas 2D
- ゲームロジック(`js/game.js`)は描画・DOMに依存しない純粋な状態machineとして実装し、Node上で直接ユニットテスト可能
- PWA対応(`manifest.json` + `sw.js` でオフライン動作・ホーム画面追加に対応、ネットワーク優先キャッシュ戦略)
- 外部ライブラリ・フォント・画像アセットのネットワーク依存なし

```
mega-merge/
  index.html
  css/style.css        筐体・HUD・サイズ選択ボタン・遊び方ダイアログのスタイル
  js/
    game.js             ゲームロジック(描画非依存、テスト対象)。合体解決・重力・列詰めの純粋関数、
                         盤面サイズ切り替え(setGridSize)・サイズ別自己ベスト記録(getBestShots)を含む
    render.js             Canvas描画(数字・色分け・ホバーセルハイライト・CHAINラベル・黒猫ロゴ)
    app.js                 ゲームループ・入力(タップ/クリック/数字キー/サイズ選択ボタン/遊び方ダイアログ)・
                            合体のアニメーション再生(効果音を音階で各段階に同期)・自己ベスト更新時の
                            紙吹雪演出・PWA登録
  icons/cat-logo.png     盤面が最後の1個になったときに表示する黒猫ロゴ(サイトルートのassets/logo.pngと同一)
  manifest.json / sw.js  PWA設定
  test/                  ロジックの回帰テスト(フレームワーク無し)
```

### 盤面サイズの切り替えについて(実装メモ)

`GRID_ROWS`/`GRID_COLS`/`CELL_W`/`CELL_H` はESモジュールの**ライブバインディング**
(`export let` + 再代入)として実装しています。`setGridSize(rows, cols)` を呼ぶとこれらの値が
更新され、他ファイルが `import { GRID_ROWS } from './game.js'` のように読み込んでいる場合でも
再importなしに最新値が見えます。盤面の実ピクセルサイズ(`FIELD_W`/`FIELD_H`、Canvasの解像度)は
サイズによらず固定で、代わりにセル1個分のサイズ(`CELL_W`/`CELL_H`)が盤面サイズに応じて伸縮します
(4×4ほどセルが大きく、6×6で現行のサイズに戻ります)。

## 既知の簡略化・今後の案

- 今後の拡張案として、ブロック全体が徐々に降りてくる「降下モード」も検討可能(現状、重力は列の中だけ・列の詰めは水平方向のみ)
- 初期盤面はランダム生成(2,2,2,4,4,8の重み付き抽選)。特定のパズルが必ず解けることは保証していない
- 連鎖ボーナス倍率は、v2時点のシミュレーションを根拠にした調整値で、今後のバランス変更の余地がある
- ショット数に上限は無く、理論上はどれだけ下手に打っても(重力・列詰めのおかげで)いつか必ず最後の1個まで到達できる
- 合体したブロックの値には上限が無い。桁数が増えるほどブロック内の文字は自動的に小さくなるが、
  極端に桁数が増えた場合の見やすさは実用上の範囲でのみ確認している
- アニメーション再生中はタップ/キー入力を一時的に無視する(連打してもショットは消費されない)
- 盤面サイズを切り替えると(アニメーション再生中を除き)即座に新しいゲームが始まる。プレイ中のサイズ変更に
  「本当に切り替えますか」のような確認は挟んでいない(カジュアルなパズルという位置づけのため)
